# Contributing to NextJsHx

NextJsHx is in foundation work and has no supported release yet. Read
[AGENTS.md](AGENTS.md), the active Beads issue, and the relevant PRD sections
before changing architecture, compiler behavior, generated ownership, or public
API.

Read the normative [architecture](docs/architecture.md) and accepted ADRs before
changing an established integration or ownership contract.

Security vulnerabilities follow the private process in
[SECURITY.md](SECURITY.md). Never put vulnerability details, live credentials,
private data, or exploit payloads in a GitHub issue, pull request, CI log,
generated artifact, or Beads record.

## Bootstrap

Install the locked development dependency and the exact local safeguards:

```sh
npm ci
haxelib install formatter 1.18.0
npm run hooks:install
bd prime
```

The hook installer is idempotent and keeps `core.hooksPath` on
`.beads/hooks`, where the tracked repository checks run before the
Beads-managed hook section.

## Work through Beads

The PRD records product intent; Beads records live ownership and execution
state. `.beads/issues.jsonl` is a passive export, not the synchronization
protocol.

```sh
bd ready
bd show <id>
bd update <id> --claim
```

Keep work inside the issue outcome and acceptance criteria. Record discovered
follow-up with `bd create` instead of widening scope or leaving a Markdown TODO.
Do not hand-edit the Dolt database, use `bd import` for routine sync, or publish
issue data with a raw `bd dolt push`.

## Typed, framework-native changes

- Keep the result an ordinary Next.js application.
- Use `nextjs.raw.*` for faithful public bindings and `nextjs.*` for justified
  typed ergonomics.
- Do not use `Dynamic`, `Any`, `untyped`, broad `unknown`, reflection, or
  unchecked casts as a design shortcut.
- Reduce generic compiler gaps outside Next.js and fix them in `genes-ts` with
  both TypeScript and classic-JavaScript evidence.
- Generate only deterministic, manifest-owned files and fail closed on native
  file collisions.
- Treat sibling repositories as read-only references unless explicitly
  authorized.

The exact version and evidence contract lives in
[support_matrix.json](support_matrix.json). Validate it without requiring any
sibling checkout:

```sh
npm run test:support-matrix
npm run support:discover
```

Edit the matrix rather than its generated documentation, then run
`npm run support:docs`. Source-oracle jobs must opt in with
`npm run support:require-genes` or `npm run support:require-upstream`.
Run `npm run drift:next:stable` for the blocking installed-package report and
`npm run drift:next:upstream` for the separate source/canary report. Never make
the upstream lane green by updating the stable baseline: inspect every
classification, its owning Bead, and its fixture first.

Public Next.js bindings start from the reviewed
[entrypoint inventory](docs/binding-policy.md), never from a recursive scan of
the installed package. Validate ordinary work with
`npm run surface:next:check` and `npm run bindings:next:check`. Use
`npm run surface:next:update` or `npm run bindings:next:update` only after
reviewing and explaining each intentional package, export, kind, stability,
Haxe mapping, safety override, generated byte, or signature change. Changed
binding IR requires an exact old/new hash entry in `acceptedTransitions`; do
not accept a generated diff merely because it matches the current
installation. New TypeScript syntax needs a generalized parser rule and a
reduced positive/negative fixture before it may generate Haxe.

An unchanged public signature that moves between `next/dist/**` declaration
files is compatible evidence, not a public import path. A missing export,
changed export kind, or changed signature is blocking stable drift. The
upstream/canary job is deliberately non-blocking, but its JSON and Markdown
report must still be produced and must retain the exact owner and fixture for
follow-up.

Hand-shaped raw externs must also be registered in
`config/next-binding-implementations.json` with exact signature hashes, source
outputs, owner, fixture, and a specific reason they require curation. Keep the
raw contract faithful while using Haxe to improve discoverability and move
safe failures earlier; document any intentional narrowing that smooths a
verified Next.js shortcoming. For the core/navigation surface, run
`npm run test:next-core-navigation` in addition to the inventory and IR checks.
For component, lazy-loading, Script, or font bindings, also run
`npm run test:next-components`; the fixture must prove direct public imports,
positive TSX use, focused Haxe failures, and failures from Next's strict
TypeScript declarations where Haxe cannot express the complete constraint.
For Web, request-context, cache, proxy, or Route Handler bindings, also run
`npm run test:next-server`; keep async return types exact, separate read-only
and mutation-capable views, preserve native Web/Next values, and include a
negative control when the Haxe layer deliberately closes an upstream typing
gap.

For semantic Cache Components declarations, generated cached-function refs,
or module/function directive rendering, also run
`npm run test:cache-boundaries`. Keep shared, private, and remote capabilities
explicit; put request reads outside shared/remote functions; preserve closed
serializable argument and result types; and require a strict Next build plus
runtime cache-key reuse and invalidation evidence. NextJsHx must not introduce
a parallel cache runtime or silently rewrite native Next configuration.

For Haxe `@:next.route` declarations, HTTP method adapters, or semantic
`RouteContext` changes, also run `npm run test:route-handlers` and the stable
fixture. Preserve lower-camel Haxe ergonomics, exact source diagnostics,
Promise-shaped params, and ordinary Next named exports without casts or a
custom routing runtime.

For `@:next.page` or `@:next.layout`, semantic props, render validation, or
injected page href changes, also run `npm run test:page-layouts`. Preserve
Promise-shaped Next inputs, exact route params, readonly raw URL input,
Element/Promise results, and implementation-only delegation in the plan.

For maintained application behavior, error/loading/not-found UX, mutations,
or cache visibility, also run `npm run test:example:todoapp:e2e` against a
fresh production build. Keep Playwright retries at zero, mutable state and
cache identities isolated per test, and browser page/console/hydration,
request, and unexpected response diagnostics teardown-fatal. Classify a known
framework cancellation or deliberate failure by exact marker and route. Never add a broad console or network-error allowlist to make the suite green.

## Before closing work

Run the issue-owned tests and the root gates:

```sh
npm test
npm run format:haxe:check
npm run public:preflight
```

Pre-commit formats and re-stages only fully staged repository-owned Haxe files,
rejects whitespace and machine-local absolute paths, scans staged content, and
runs only fast contracts selected by the staged paths. Pre-push scans every
reachable Git revision and decoded Beads history, then runs
`npm run test:prepush`. Full Next builds, browser tests, framework matrices, and
the complete integration harness belong to CI and `npm run public:preflight`.

Before publishing Beads data, use:

```sh
npm run beads:install-pinned
npm run beads:push
```

That wrapper scans Git history plus decoded current and historical Beads
records before invoking `bd dolt push`. The installer builds reviewed upstream
merge commit `7eb428cde13c6d2c4743a76533be8df2d418aff5`, which contains the
generalized NULL-history fix from Beads PR #4912. It verifies the source
archive's SHA-256 and the built binary's embedded identity, installs only under
this repository's ignored `.cache/`, and never replaces the user's global
`bd`. Replace the temporary commit pin with the first stable Beads release
containing the fix.
